Dental clinic queue system

System design overview. Prototype for a localhost demo.

1 Architecture2 How it connects3 System flow4 Database design5 Redis design

1. System architecture

Three screens share one React app. It talks to one Node.js backend, and the backend reads and writes MongoDB and Redis.

MongoDB keeps the permanent record (tickets, staff, rooms). Redis keeps the live queue (numbers, order, who is being served) and tells Socket.IO when something changes.

5. Redis design

Redis holds only today's live queue. If it restarts empty, the server refills it from MongoDB.
